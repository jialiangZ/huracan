## 0. 现在的执行目标

第一轮只回答：**在相同数据、主干和训练预算下，背景集合的相关结构是否比均值＋逐点方差带来额外收益？**

执行顺序：

`P0 数据与评估修正 → P1 修正后的基线 → P2 背景缓存与诊断 → P3 输入端融合对照 → P4 自身背景循环 → P5 来源共享误差 → P6 主干内融合`

P3 得到可信结果前，不增加卫星数据、不迁移 GenCast、不改 SFNO 谱核、不同时做长循环全模型联合训练。P5、P6 由前面结果触发，初期不需要全部完成。

### 全部实验统一的时间协议

- 输入状态：`(t−6h, t)`；单次输出：`(t+6h)`；`model.outputs_per_call: 1`。
- 每次调用前进 6h，下一次状态对为 `(t, t+6h)`。L 次调用的数据窗口为 `2+L` 帧，目标为后 L 帧。
- 每次只把 `(t−6h, t]` 内的观测视为新增证据。保留实际时间偏移；下一次新增窗口为 `(t, t+6h]`。
- 若接口仍保留 `obs_tm1/obs_t` 两个槽位，历史槽位须明确标为上下文，或在新增证据分支屏蔽。不能因输入有两帧状态就每步重复累加旧观测。所有方法使用相同规则。
- 训练输出集合成员 M=2，表示同一目标时刻的两个样本；不是两个输出时刻。

| 日历跨度 | 单步输出下的调用数 |
|---|---|
| 6h / 12h / 24h / 48h | 1 / 2 / 4 / 8 |
| 1 天 / 3 天 / 4 天预报或展开 | 4 / 12 / 16 |
| 30 天 / 60 天 / 90 天循环或 spin-up | 120 / 240 / 360 |

沿用日历配置时由统一时间工具计算，不再硬编码每次调用的小时数。仅更改 `outputs_per_call` 不会自动保持原 rollout 整数代表的日历跨度，必须逐阶段检查。释放预报的总调用数包含产生 t+6h 的首个融合调用。

### 2.2 同时完成的必要数据审计

- 对照 [NOAA ISD-Lite 格式](https://www.ncei.noaa.gov/pub/data/noaa/isd-lite/isd-lite-format.pdf) 和 [IGRA 格式说明](https://www.ncei.noaa.gov/pub/data/igra/data/igra2-data-format.txt)，逐项核对固定列、所有缺测码、RH 单位、气压／高度、未知发报小时和 QC 标记。本轮未完整核验 IGRA 字段，不将这些项目假称为已修复。
- ISD-Lite 不一定保留完整 QC 元数据，缺失标为 unknown，不伪造质量分数；需要更丰富来源信息时再读取原始 ISD。
- 检查物理单位下的位势等变量是否超出 float16 范围。WB2 路径保存 fp32；另一个 ERA5 预处理路径写 fp16，必须审计。物理状态建议保留 fp32，归一化后的缓存才考虑 fp16。
- 四年每六小时连续数据应按 `times.json` 计数。2010—2012 完整日期有 4384 帧，现有 4380 不是精确年界；避免依赖注释里的年份解释。
- normalizer 当前每 8 帧采样可能总选同一个日内时刻。改成训练期流式统计或平衡覆盖 00/06/12/18 UTC 的抽样，所有方法共用。
- 训练损失当前是简单空间平均，Gauss 网格并非等面积。共同修正版使用面积权重；保留旧基线结果作记录，不能把统一修正损失权重算作新方法贡献。
- ESSR 要明确采用 RMS spread / RMSE，还是平均局地标准差 / RMSE；代码当前为后者。推荐前者作为主诊断，同时明确有限集合效应，不能只看是否等于 1。

### 2.3 数据划分与 checkpoint 策略

最低可行数据划分为 2010—2011 训练、2012 验证、2013 测试，日期索引自动生成；仅在所有相关模型均未使用 2013 时，该年才是严格未见测试。若现有模型训练用了 2010—2012，则可以维持 2013 做开发验证，另下载尚未使用的年份作为最终测试。训练过的年份不能靠改配置重新变成未见数据。

Dataset 以完整窗口 `[t0−1, t0−1+frame_window)` 归属于一个 split 为最简单规则；单输出 L 次调用时 `frame_window=2+L`。循环 spin-up 与验证计分期另行登记：早于计分期的无梯度历史可以作为明确声明的 spin-up，但任何训练损失不能接触验证／测试期。最后测试前冻结预处理、超参数和主指标。

**P0 交付物：**数据审计表、修正项的回归测试、日期划分 manifest、指标定义说明、每年每变量有效观测计数与异常率。通过后才进入方法比较。

## 3. P1：建立修正后的 R0 基线

使用原 `HuracanSFNO` 拼接编码结构，应用 P0 的共同修正。训练／复用规则：不受问题影响且训练年份合规的 checkpoint 可复用；否则从相应最早受影响阶段重训。纯 ERA5 预报模型未见观测解析问题，但仍需核对 normalizer 和训练标签范围。

阶段链通常为 `deterministic → stochastic → fcst_ar` 与 `stochastic → assim`；初期固定预报模型，不进入 joint。不要盲用当前 `--phase all`：当前入口使用 `ALL_PHASES`，还包括需要另行验证数据语义的 hybrid。

先重现三个对照：正常观测、观测旁路、独立 forecast 模型。观测旁路和 forecast 模型是不同对照，原同化网络零输入不自动等于 forecast 网络。新增的 count/mask 必须同步清零。

在验证期四季各选择一个连续窗口，统一起点、spin-up 和随机种子。先用 8 成员、3 天释放预报检验。只有一个起报时刻的 scorecard 不用于决定研究成败。

**P1 交付物：**基线 checkpoint 与数据版本、跨季节指标、正常／旁路／forecast 对照、显存与吞吐记录。若模型基本不能利用观测，应先查数据、训练和输入接口。

## 4. P2：缓存背景集合，先验证它包含有用结构

### 4.1 缓存内容与因果顺序

新增 `scripts/cache_background.py`（待实现），从修正后的单输出 R0 生成集合轨迹。对每个样本，在吸收当前新增观测窗口之前保存：

```text
sample_id、两个状态的时间、当前观测窗口、checkpoint/data/normalizer 哈希
background: [K=8, 2, N=4608, C=72]
forcing:    [2, N, 3]
obs / obs_mask / count / time_offset 或事件记录索引  # 新增窗口 (t−6h,t]
target:     [1, N, 72]              # t+6h 单个未来场，仅供损失
```

输入背景必须来自过去循环输出；不能把两帧 ERA5 真值重复 8 份当作集合。初始 spin-up 在样本清单中单列，评估其敏感性。普通基线成员独立，因此可以逐成员生成到磁盘，再按相同时间合并，不必同时驻留 8 份训练图。

一次调用读取 `(t−6h,t)` 的背景与新增观测 `(t−6h,t]`，输出 t+6h；下一次使用 `(t,t+6h)` 的状态对和 `(t,t+6h]` 的新增观测。保存的背景不得已经融合当前新增窗口；前一窗口的信息可以已经包含在背景中，但不能再次作为独立证据计数。任何利用未来 target 计算的诊断量都不得进入缓存的模型输入字段。

缓存保留显式时间轴：单次 target 为 `[1,N,72]`，L 次展开为 `[L,N,72]`；训练预测为 `[B,M,L,N,72]`。如果实际模型返回单元素 tuple 或省略单步时间轴，适配层统一还原该数据约定，避免把 M 与 L 混淆。

### 4.2 缓存规模与显存

以 8 成员、两帧、4608 网格点、72 通道计算，归一化 fp16 背景约 **10.6 MB／样本**，1000 个独立样本约 10.6 GB，尚不含目标等内容。相邻样本有重叠，优先按时间保存轨迹、按需组窗，避免重复存储。

从 300—1000 个跨季节样本做筛查，再扩大数据；这只是诊断规模，不能直接支撑最终泛化结论。磁盘分片读取到 CPU，按 batch 传 GPU。当前 runner 会把整个窗口传 GPU，长循环时应改为按帧／小块传输。

### 4.3 三项诊断与门槛

1. 集合方差与绝对／平方背景误差的关系，按季节、变量、区域分层。
2. 固定局地表示下，秩 4 模式投影解释的误差比例；对比相同秩和范数的随机子空间及仅方差基线。这个使用真值的投影是事后上界诊断。
3. 对真实观测做匹配覆盖的稀疏化、站点留出；比较误差与集合离散度变化。先用原观测值，不立即加人工偏差。

如果模式几乎不含额外信息，检查集合是否塌缩、局地窗口是否不合适、尺度是否被 coarse grid 消除。不要直接增加更多网络模块。诊断有信号，再开始 P3；不能仅凭事后投影较好就宣称可学习收益已成立。

模型第一版接口建议为 `step(..., bg_context=..., obs_context=...)`，沿用用户已适配的 t+6h 单输出接口；两帧状态与 forcing 输入保持不变。空间局部化先复用 6×12 的窗口作为原型，注意经度周期与纬度边界。只在输入编码后插入一次融合；主干内注入等 P6。

### 5.2 最小可实现的融合机制

共同表示维度 d=32，背景成员 K=8、模式秩 r=4。用共享局地线性投影获得成员表示及协方差；diag 版本使用同一协方差的对角部分，mode 版本保留主要非对角结构。先固定／冻结表示投影来隔离结构作用，有收益再统一训练投影。

观测编码与学习到的局地读取关系产生 `z_i` 和 `A_i=R_i U_b`，累积正定的潜空间证据，得到模式系数分布，映射成隐藏状态修正；同样保留受约束补充残差通道。误差方差限制正值、上下范围与正则；稳定求解用 Cholesky，不对低秩矩阵直接求逆。

第一轮不加入来源 b_g，先跑 R1、R2、R-attn。网格观测可先复用，但必须有独立 mask/count/time；此阶段不声称验证了原始点观测的来源一致性。获取原始事件表后，同样的观测编码与数据预算用于全部相关对照。

离线第一版的 R1/R2/R-attn 统一以背景均值两帧作为主干状态输入，K 个成员通过 context 提供信息；同一 t+6h 时刻的两个集合输出样本使用独立噪声。这样，在固定 context 下输出抽样条件一致。后续若改用成员状态作为输入锚点，需要统一抽样规则；在线相互作用集合的成员不能直接视为独立同分布。R0 的单步输出、逐成员实现单独保留为系统参照。

|---|---|---|
| 网格、主干 | 48×96、hidden=192、6 blocks | 保持 checkpoint 兼容；不直接换分辨率 |
| batch size | 1 | 先测显存，再考虑 2 |
| 背景成员 K | 8 | 离线生成并缓存，不保存生成器训练图 |
| 训练输出成员 M | 2 | 同一 t+6h 时刻的独立噪声样本；单次输出时间步数为 1 |
| 评估输出成员 | 8 | 全组一致，逐成员／小批生成 |
| 训练展开 | 1 call | 仅输出 6h；随后测 2、4 calls，分别覆盖 12h、24h |
| 学习率 | 新模块 1e−4；解冻层 1e−5 | 候选起点，按验证集调整；基线同等调参预算 |
| 微调范围 | 融合＋必要输入投影；随后最后 1—2 blocks | 预报模型固定，新增模块优先 |
| 精度 | 先沿用 fp32＋现有 checkpointing | 复数 SHT 的混合精度另行数值验证 |
| 筛查预算 | 每组 2000 optimizer steps，1 seed | 仅做筛查；未收敛需统一延长预算 |
| 确认预算 | 入选组 5000 steps 起、3 seeds | 不等于保证充分训练；报告验证曲线 |
| 验证频率 | 每 250 steps | 同一验证样本与种子表，不查看测试集 |

先用 50—100 步完整前向／反向做性能测量，丢弃首次缓存与初始化耗时。记录 `max_memory_allocated`、`max_memory_reserved` 和实际设备占用，建议至少留 2—3 GB 余量。

冻结主干参数不等于无需穿过主干反向传播。插在主干前的可训练模块仍需梯度路径。现有 Lightning 代码采用 manual optimization，每 batch 清梯度；梯度累积必须显式实现，不能只依赖 Trainer 的一个选项。若显存不足，先减 batch／展开长度，再考虑经过验证的混合精度；不先改变模型宽度导致 checkpoint 不兼容。

### 5.4 公平的实验清单

| ID | 内容 | 最关键比较 |
|---|---|---|
| R0 | 修正后的原架构 | 系统参照 |
| R1 | 同一新接口，均值＋方差，独立观测误差 | 简单不确定性已能做到什么 |
| R2 | R1 加入背景相关结构，其他部分匹配 | 主机制是否成立 |
| R-attn | 原始同一集合、同一观测与元数据的强 attention | 是否优于普通集合输入网络 |
| R-inflate | 最强简单接口＋验证集调参的方差／误差膨胀 | 是否只是校准修正 |

R1/R2 在非模式设置下尽量匹配容量；参数、FLOPs、每步耗时一起报告。相同背景缓存、训练时间样本、输出成员噪声表、训练步数及解冻层。先 1 seed 排查实现，再对关键比较做至少 3 seeds；不能只重跑新方法的最佳种子。

公平定义应以信息截止时刻一致为前提：截至 t 的观测用于一次融合调用，得到 t+6h；继续以 `(b_t, x_(t+6h))` 调用固定预报模型一次，得到 t+12h，期间不加入新观测。总计 4/12 次调用分别到达 t+24h/t+72h，其中首个为融合调用，其余 3/11 次为 forecast 调用。若 runner 把“循环结束后再 forecast”的第一个输出标为 lead=6h，应核对它是否实际上已是相对最后观测截止点的 12h；结果必须同时记录 cutoff time、forecast initialization time 与 valid time。

## 6. 初步实验与需要拿到的图表

### E0：数据与指标验收

完成 P0 表中的回归测试。输出标准化日期范围、split 完整窗口、缺测／零值／时间匹配统计，以及 CRPS 手算结果。训练端和评估端面积权重约定一致。

### E1：真实观测主对照

先在验证期四季各一个 14 天窗口评分，统一 spin-up；这 56 天用于初步筛查，最终使用独立测试年或覆盖充分的独立测试窗口。训练样本均衡覆盖训练期季节。

主要变量预先固定为 `2t、t850、z500、u850、v850、msl`，其余变量一并附表。记录单次融合的 6h 输出，以及固定同一观测截止点、继续自回归得到的 12h/24h/72h 预报。持续同化时在下一周期加入新观测所得的场另列结果，不能与无新增观测的释放预报混算；不只挑表现最好的变量。

需要三张图：各方法相对 CRPS skill；误差与离散度关系；不同背景不确定性分箱下 R2 相对 R1 的收益。若只增加 spread 而均值误差和观测验证无改善，继续分析，不能直接宣布机制成立。

### E2：方向机制实验

先在已有 Lorenz-96 或简化已知真值问题上建立相同均值／对角方差、不同协方差的两个问题实例；各自的真值生成机制必须与对应先验匹配，不在同一真值上任意替换先验后要求模型“必须变好”。检验输出是否随正确方向信息变化，并与解析或数值参考比较。该实验中的合成观测仅用于机制验证。

真实天气使用缓存的正常集合做主评价；额外打乱不同位置／变量的成员对应关系可保留逐点边际分布而破坏相关结构，作为反事实诊断。它可能破坏物理一致性，只能辅助解释，不能当作原生业务性能。

### E3：先做两种温和的真实网络变化

第一轮仅做站点／报告组留出和匹配覆盖的稀疏化。选择规则只用位置、来源和预先固定随机种子，不根据测试误差筛选。所有方法得到同一观测子集；源数据值保持真实。暂不进行大量偏差强度组合扫描。

### 初步通过标准

建议在运行新方法前登记：验证主分数为指定变量和时效的平均相对 CRPS skill，R2 对 R1 达到约 1% 改善且无持续超过约 2% 的关键变量退化，作为继续投入的参考。同时要求对强 attention 的比较具有收益或明确的成本／泛化优势。

阈值是工程选择，不是显著性或发表保证。按天气过程／时间块做配对 bootstrap；窗口少、置信区间宽时增加独立窗口。测试集不反复用于调参数。若收益不能超过训练种子波动，结论为“尚无足够证据”。

## 7. P4：将有效融合接入自身背景循环

当前 `core/rollout.py` 的训练和推理都以成员循环在外层，每个成员跑完整条轨迹。跨成员融合必须改成时间循环在外层：

```text
所有成员到达相同输入时刻
→ 用吸收当前观测前的 K 个背景构造唯一 context
→ 固定该 context，逐成员／小批更新，期间不让它被已更新成员污染
→ 完成所有成员后，状态对从 (t−6h,t) 更新为 (t,t+6h)，整体推进 6h
```

增加同步时间、成员排列和 no-future-information 测试，并核验每次只推进一帧。对单输出滑动接口，另测相邻调用的旧观测不会被再次累积为新增证据。离线缓存用于同背景对照；上线后各方法使用自身轨迹，二者结果分开报告。

训练阶段不要求在 4090 上保留 K=8 的完整多步计算图：先在线维护无梯度的背景池，选择两个集合输出样本训练，每个成员每次只输出一个未来场，明确在哪些步 detach；各组使用同样策略。它属于截断／半梯度训练，不能宣称完整端到端梯度。后续有资源再比较更长梯度展开。

先 2、4 calls（12h、24h）的短循环，必要时到 8 calls（48h），再评估连续 30 天（120 calls）。不每日用 ERA5 重置。中断 1/2/4/8 calls 对应 6/12/24/48h；需要 96h 场景时用 16 calls。中断观测时同步关闭值、mask、count 及事件信息，历史观测上下文也按统一中断协议屏蔽，避免旁路泄漏，并使用训练时覆盖的空观测处理；恢复后报告误差曲线和预报收益。

## 8. P5：来源共享误差，数据具备后再做

新增逐记录事件表，至少保存 `record_id、station/report/platform_id、time、lat/lon、variable、level、value、valid、QC（可空）`。保留原网格管线作为对照；独立 count、时间偏移、元数据也提供给强基线。

建议新增 `huracan/data/events.py`、`huracan/core/evidence.py`，分别负责事件读取和联合信息累积。初期按同站同窗口或同次探空报告组织可追溯分组；分组不等于已经证实存在共享误差。不要添加可以记忆训练站点偏差的自由 station embedding 作为默认方案。

补齐完整 2×2：R1（diag＋独立）、R2（mode＋独立）、R3（diag＋来源共享）、R4（mode＋来源共享），加简单相关模型和稀疏化基线。来源项维度先 2，再试 0/4；同来源跨批次必须共享同一潜变量，合并联合统计后再消除。

验收：记录去重不影响独立同值测量；重排／分批不改变最终证据；浮点误差按 dtype 预设容差；固定随机输入下推理一致。真实观测留出验证与已知注入偏差诊断分开。没有真实泛化收益时，不保留来源项作为主贡献。

## 9. P6：是否进入 SFNO block 内部

只有 P3/P4 有稳定收益，再比较：输入端单次注入、输入端＋第 2/4 个 block 后注入。保留谱滤波和 Swin 本体，用当前隐藏状态查询固定背景／证据 context：

`h_next = SFNO(h) + Fusion(SFNO(h), obs_context, bg_context)`。

先计算 SFNO 输出一次，不重复计算。不同层只读取同一证据，不把来源精度重复加到后验。匹配参数预算或给出容量对照，记录反向传播显存。无稳定额外收益就保留输入端方案，不为“改得更多”而扩大模型。
